# Claude 账号防封指南（IP · 付款 · 浏览器环境）

Anthropic 对 Claude（网页版、Claude Desktop、Claude Code）的风控本质上是**多维关联打分模型**——单点异常有时不会立刻封号，但 **IP 脏/跳变 + 付款通道高危 + 浏览器/系统环境矛盾** 叠加时，极易触发秒封（俗称“露头就秒”）或账单风控直接退款封号。

下面按 **IP、付款、浏览器环境** 三个核心维度，拆解触发逻辑与实操避坑准则。

---

## 一、IP 与网络出口逻辑

Anthropic 会同时检查 **IP 归属地、ASN 类型（机房 vs 住宅）、滥用黑名单记录、以及 IP 漂移轨迹**。

### 1. 高危雷区（最容易秒封）
- **受限地区 IP 漏出**：中国大陆（CN）、香港（HK）、澳门（MO）、俄罗斯（RU）、白俄罗斯（BY）、伊朗（IR）、朝鲜（KP）等地区只要漏出过一次（哪怕是登录前的预览、遥测或代理闪断回落直连），账号就会被直接标记。
- **万人骑机场节点 / 脏数据中心 IP**：常见廉价机场节点同一 IP 上每天有几百人注册/登录/高频刷 Claude，ASN 已被标为高风险 DataCenter / Proxy，注册或绑卡瞬间触发风控。
- **短时间跨洲瞬移**：早上用美国西海岸，中午切日本，晚上切德国——这种“地理瞬移”对新号和刚付款的号极其致命。
- **IPv6 / UDP / DNS 泄露**：代理只管了 IPv4 TCP，但系统或浏览器通过直连 IPv6 或本地 UDP 53 暴露了真实地区。

### 2. 最佳实践
- **首选洁净度排序**：海外原生家宽静态住宅 IP（ISP/Residential） > 干净独享双 ISP / 静态机房 IP > 机场解锁节点（仅建议做前置，**最佳实践是「机场前置 → 静态住宅 IP 落地」链式代理**）。
- **固定国家/城市，不乱切节点**：一个账号长期绑定同一个国家/城市（最好是固定静态 IP），在 `edualc` 的「出口与订阅 → 出口防漂移策略」里直接点 **「绑定当前出口」** 锁死。
- **严格 Fail-Closed（断网不直连）**：绝不允许代理断开时自动回退直连（`DIRECT`）。
- **一账号一环境/一出口**：如果手里有多个号，不要让多个账号在同一时间、同一脏 IP 上频繁切换登录，防止连坐。

## 二、付款与账单逻辑（Stripe / App Store / Google Play）

很多人环境全绿、IP 很干净，但**付完款几分钟到 48 小时内被退款封号**，90% 问题出在支付风控（Anthropic 网页端底层走 Stripe Radar 实时反欺诈引擎）。

### 1. 高危雷区
- **国内双币卡 / 泛滥虚拟卡头（BIN）**：国内发行的 Visa/Mastercard 或市面上被薅烂的共享虚拟卡 BIN，在 Stripe 风控库里拒付率极高，极易直接触发高危拒付判定。
- **淘宝 / 闲鱼低价代充与成品号**：大量黑卡、盗刷卡或同一张卡批量给几十个号代充，一旦上游有一笔拒付，整批关联账号全部连坐清退。
- **账单地址与出口 IP 严重冲突**：挂着日本 IP，却填美国免税州地址，再用欧洲虚拟卡付款——Stripe 会把 **IP 地区 + 卡 BIN 发行国 + Billing Address 邮编** 做交叉比对，三者全不匹配分值极高。
- **频繁换卡 / 连续扣款失败重试**：连续尝试 2~3 次被拒卡还继续硬试，账号会被 Stripe 直接拉黑。

### 2. 最佳实践（按稳妥程度排序）
1. **最稳方案：美区 Apple ID + iOS App Store 礼品卡内购订阅**
   - 由 Apple 统一代收，**完全绕开 Stripe 卡头和账单地址交叉审查**，几乎不会因为信用卡 BIN 被风控；
   - 手机开干净美区出口，用正规渠道购买的美区 Apple Gift Card 充值后在 Claude iOS App 内订阅 Pro / Max，订阅成功后电脑端（网页 / Desktop / Claude Code）通用。
2. **次稳方案：海外本人实体借记卡/信用卡（或 Google Play 礼品卡）**
   - 确保 **出口 IP 国家、卡发行国、账单地址邮编** 尽量一致（例如美区 IP + 美区卡 + 真实格式的美区免税州如 Oregon / Delaware 地址）。
3. **养号节奏**：
   - 新注册账号不要第 1 分钟就绑定陌生虚拟卡直接冲 Max；先用干净 IP 正常完成邮箱/手机验证，免费用 1~2 天后再订阅更稳。
   - **付款那一刻的 IP 必须干净且与日常使用一致**，不要为了省事关掉代理或临时换一个随机节点去付款。

## 三、浏览器与运行环境指纹逻辑

即使 IP 在美国、卡也没问题，浏览器和客户端上报的本地环境如果暴露了“中文东八区宿主机”，照样会被判定为代理伪装。

### 1. Anthropic / Cloudflare 会采集的环境矛盾点
| 维度 | 常见翻车表现 | 正确对齐标准 |
| :--- | :--- | :--- |
| **时区（Timezone）** | IP 在美国洛杉矶，但 `Intl.DateTimeFormat().resolvedOptions().timeZone` 返回 `Asia/Shanghai`，`getTimezoneOffset()` 为 `-480` | 必须与出口 IP 一致（例如 `America/Los_Angeles`） |
| **系统与浏览器语言** | IP 在美国，但 `navigator.languages` 是 `["zh-CN", "zh"]`、`Accept-Language` 带 `zh-CN` | 与出口地区一致（例如 `en-US,en`） |
| **WebRTC 真实 IP 泄露** | 网页脚本通过 STUN 服务器绕过 HTTP 代理，直接拿到宿主机局域网/公网真实 IP | 强制禁用非代理 UDP（`disable_non_proxied_udp`）+ 容器层阻断公网 UDP |
| **宿主机 Cookie / 指纹残留** | 在宿主机日常 Chrome 里登过曾被封的 Claude 账号，残留 Cookie / IndexedDB / LocalStorage / 设备指纹 | 彻底隔离浏览器环境，不与宿主机日常浏览器混用；换号用全新独立配置目录 |
| **旁路遥测泄露** | 主请求走了代理，但本地 CLI/App 的更新检查、Sentry、Statsig 走了宿主机直连 | 物理隔离无公网网卡 + 禁用非必要遥测环境变量 |

### 2. 最佳实践
- **登录、浏览、对话全在隔离环境内完成**：不要在宿主机日常中文浏览器里打开 `claude.ai` 或完成 OAuth 授权。
- **不要过度使用“魔改反指纹插件”**：把 Canvas / WebGL / Font 全改成随机乱码反而像机器人/爬虫；**真实、纯净、时区语言与 IP 一致的原生 Chromium / 官方客户端**才是最自然的指纹。
- **善用环境自检**：在 `edualc` 里跑 `edualc browser https://fuck-claude.vercel.app/`，确认页面里 **IP 地区、时区、语言、WebRTC** 全绿一致后再登录和日常使用。

## 四、配合 `edualc` 的日常防封操作清单

1. **先配干净出口再登录**：打开 `http://127.0.0.1:8317/ui` → 导入订阅（**强烈建议配合「链式落地静态住宅 IP」**）→ 确认 **10/10 绿灯放行**。
2. **锁定出口防漂移**：在「出口与订阅 → 出口防漂移策略」点击 **「绑定当前出口」**，防止节点漂移到其他国家。
3. **全程在隔离环境内登录**：
   - 登录 Claude 桌面端：直接在控制台 **「Claude 桌面端」** 页完成登录（点击登录会自动拉起同步好时区/语言的内置 Chromium）。
   - 登录 Claude CLI：在终端执行 `edualc login default`（同样走内置隔离浏览器完成 OAuth 回调）。
4. **付款走正规稳定通道**：优先 iOS 美区 App Store 礼品卡订阅，避免廉价代充和脏虚拟卡。
5. **保持自然个人节奏**：个人写代码/对话单人单并发非常安全，不要开高并发脚本 24 小时狂刷，也不要把个人订阅分享给多人异地同时用。
